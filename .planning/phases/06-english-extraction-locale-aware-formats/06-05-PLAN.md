<objective>
Make the search accent-insensitive, without moving the sort order and without breaking the
highlight.

Purpose: this is the phase's ONE intentional behaviour change. A user who types "elodie" must find
"Élodie" — the requirement the roadmap states as SEARCH-01. The change is small, but it has a trap
the CONTEXT documents explicitly: `hl()` computes the `<mark>` window against the ORIGINAL
lower-cased text, so the moment the query is folded the offsets no longer line up and the
highlight lands in the wrong place. This plan folds both sides with ONE helper, uses the folded
string for the comparison AND for the highlight, and maps the folded offsets back to the original
characters so the `<mark>` is exactly where it was.

Output: `foldForSearch()` in `src/core/utils.js`, the rewritten `hl()` in `src/ui/helpers.js`, the
nine comparison sites, and `test/i18n-search.test.mjs`.
</objective>

  <action>
    Add one helper to `src/core/utils.js`:

    ```js
    /* The search folds both sides: NFD, then the combining marks are dropped, so "elodie"
       finds "Élodie". The map keeps the index of the ORIGINAL character behind every folded
       character, so a highlight computed on the folded text still lands on the right
       characters of the original string. */
    export function foldForSearch(s) {
      const src = String(s ?? '').toLowerCase();
      let text = '';
      const map = [];
      for (let i = 0; i < src.length; i++) {
        const folded = src[i].normalize('NFD').replace(/[\u0300-\u036f]/g, '');
        for (const c of folded) {
          text += c;
          map.push(i);
        }
      }
      return { text, map };
    }
    ```

    The lower-casing happens BEFORE the folding, so a character whose lower-case form is longer
    (`İ`) is folded to a single character and the map stays exact.

    Rewrite `hl()` in `src/ui/helpers.js` so the comparison and the highlight use the SAME folded
    string and the window is mapped back to the original:

    ```js
    export function hl(text, q) {
      const raw = String(text ?? '');
      const needle = foldForSearch(q).text;
      if (!needle) return esc(raw);
      const { text: folded, map } = foldForSearch(raw);
      const i = folded.indexOf(needle);
      if (i < 0) return esc(raw);
      const start = map[i];
      const end = map[i + needle.length - 1] + 1;
      return esc(raw.slice(0, start)) + '<mark>' + esc(raw.slice(start, end)) + '</mark>' + esc(raw.slice(end));
    }
    ```

    The three slices are escaped separately, exactly as the current implementation escapes the
    three parts — the catalogue values never reach this function, but a task title does, and it
    must be escaped once, not twice.

    Create `test/i18n-search.test.mjs` with `node:test` and `node:assert/strict`. It asserts the

    implementation gets wrong.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| the query → the comparison | the query comes from the user's keyboard |
| a document value → the folded text | the candidate strings come from the document, i.e. from user data |
| a candidate → the rendered highlight | the highlighted text is spliced into the page as markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-15 | Tampering | the highlighted text | high | mitigate | `hl()` escapes the three slices it renders (`esc()` on the head, the marked part and the tail), so a task title that carries markup is inert exactly as it is today; the folding never changes what is escaped |
| T-06-16 | Denial of service | `foldForSearch()` on a long string | low | mitigate | The fold is a single pass over the string's characters, done once per candidate and once per query; the search caps the task results at 30 as it does today |
| T-06-17 | Information disclosure | the query | low | accept | The query is folded in the browser and never leaves it; the change touches no network call, no stored document and no server |
| T-06-SC | Tampering | package installs | high | accept | This phase installs no package and adds no `dependencies` block; the folding uses the platform's `String.normalize` |
</threat_model>
