<objective>
Build the progress meter of the sweep, then prove it end to end on one literal.

Purpose: the sweep is ~800 user-visible literal occurrences spread over ~50 files. A single task that
sweeps everything is neither executable nor reviewable, and "did we forget a string?" is not a
question a human can answer by reading a diff. This plan builds the device that makes the sweep
mechanical and its completion provable: a static scan of the interface sources, a shrinking
allow-list of the literals that are not extracted yet, and the build gate that turns the scan into
a promise. It then proves the whole pipeline on ONE literal — catalogue, call site, allow-list,
scan, suite — so the nine later waves are copies of a path that is already known to work.

Output: `scripts/i18n-scan.mjs`, `test/i18n-scan.test.mjs`, `test/fixtures/i18n-pending.json`, the
`i18n:scan` / `prebuild` / `prebuild:en` scripts in `package.json`, and the tracer extraction in
`src/ui/toast.js` + `src/locales/en.json`.
</objective>

  <action>
    Create `scripts/i18n-scan.mjs`. It is plain Node, no dependency, and it lives OUTSIDE `src/`
    for the same reason `scripts/icons.mjs` does: the `lucideSubset()` walk in `vite.config.js`
    reads every `.js` file under `src/`, and a scanner full of English prose would sweep its own
    pattern strings into the icon bundle and change the frozen 174-name baseline.

    The module exports:

    - `scanTree(root = 'src')` → an array of findings `{ file, line, kind, text }`, one per
      detected occurrence. `file` is the path relative to the repository root, `kind` is the rule
      family that caught it, `text` is the decoded literal.
    - `scanSource(text, file)` → the same array for one file's content, so a test can scan a
      string without touching the disk.
    - `EXCLUDED_FILES` → the set of files never scanned. It holds `src/data/seed.js` (demo
      content) and nothing else.
    - `main()` → the CLI. It reads the allow-list, compares it with the findings and exits 1 on a
      violation. `--report` prints every finding with its file and line instead.

    The rule families, each one a named function so a finding names the rule that caught it:

    1. `ruleTextNode` — an HTML text node: the content between `>` and `<` inside a template
       string, trimmed, reported when it holds at least two letters and is not a pure
       interpolation, a symbol or an entity.
    2. `ruleAttribute` — the value of `aria-label`, `placeholder`, `title`, `alt` and `data-tip`,
       reported when it holds at least two letters and is not a pure interpolation. The `value`
       attribute is deliberately NOT in this family: a literal `value` is a form or machine value
       (`value="list"`, `value="board"`, `value="all"`, `value="__remove"`), and the dynamic ones
       are interpolations, which the rule skips anyway.
    3. `ruleToast` — the first argument of a `toast(...)` call, and the message argument of
       `mutate(...)`.
    4. `ruleHelperArgument` — the arguments of the documented display helpers: `empty` (its
       second and third arguments), `H`, `srow` (its first and second), `I` (its third), `tog`,
       `card`, `sk`, `miniRow`, `actHtml`, `kcard`, `pageTitle`. The helper list is a named
       constant in the module, with a comment saying that a helper added to the interface must
       be added to that list.
    5. `ruleDisplayName` — the value of an object property named `name`, `label`, `title`, `desc`,
       `text`, `hint` or `message`; plus every value of an object assigned to a const whose name
       ends in `NAMES`, `LABELS`, `TITLES` or `HEADINGS` (the display tables: `ROUTE_NAMES`,
       `ROLE_LABELS`, `STATUSES`, `PRIOS`, `LABELS`, `PSTAT`).
    6. `ruleProse` — a free-standing string literal that contains a space and begins with a
       capital letter. This is the catch-all for the labels that reach the interface through a
       helper nobody documented.

    The exclusions, each one a named function or set, applied before a finding is reported:

    - `isMachineIdentifier(text, context)` — the syntactic contexts: a comparison operand, a
      switch case, an object key, a `data-*` / `id` / `class` / `style` / `href` / `src` / `type` /
      `role` / `rel` / `tabindex` attribute value, an `ic('…')` argument, an element name, a CSS
      declaration value, a CSS custom property (`--bg`), an import specifier, a path, a URL, a
      number, a date, a duration, a regex and a lowercase kebab-case token (the icon scan's
      vocabulary).
    - `STORED_VALUES` — the stored preference values the application displays verbatim:
      `'(GMT-08:00) Pacific Time'`, `'(GMT-05:00) Eastern Time'`, `'(GMT+00:00) London'`,
      `'(GMT+01:00) Berlin'`, `'(GMT+08:00) Singapore'`, `'(GMT-07:00) Pacific Time'`,
      `'English (US)'`, `'English (UK)'`, `'Deutsch'`, `'Español'`, `'Français'`, `'日本語'`,
      and the four stored date patterns `'MMM d'`, `'d/M'`, `'M/d'`, `'yyyy-MM-dd'`. Every entry
      carries a comment saying it is a stored value, not interface text, and that phase 8
      (LOC-02, LOC-04) replaces the language list.
    - `DEMO_VALUES` — the demo content values that live outside `src/data/seed.js` and are shown
      to the user as stored data: the default member name, the default project name, the default
      workspace name. Each entry carries a comment naming why it is data.
    - a dotted catalogue key (`^[a-z][a-z0-9]*(\.[a-z][a-zA-Z0-9]*)+$`) is a lookup, never prose.

    The CLI compares the findings with the allow-list and reports three kinds of violation:

    - `pending` — a finding that the allow-list covers: acceptable during the sweep, and the
      reason the sweep is not finished yet.
    - `unlisted` — a finding the allow-list does NOT cover: a literal that was never put in a
      catalogue. This is the violation that fails the build (success criterion 1).
    - `stale` — an allow-list entry whose literal is no longer detected: the entry must be
      removed, because the list is a meter and a meter that keeps dead entries is not a meter.

    Exit 1 when there is at least one `unlisted` or `stale` violation; print the file, the line
    and the literal of every violation so the message is actionable. Exit 0 when every finding is
    covered and no entry is stale.

    Create `test/i18n-scan.test.mjs` with `node:test` and `node:assert/strict`. It must NOT

    allow-list is accepted, an unlisted finding is a violation, and a stale entry is a violation.
