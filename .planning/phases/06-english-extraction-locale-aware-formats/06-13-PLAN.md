    Sweep the two files with the protocol.

    **The permission names are STORED values.** `PERMS` in `src/overlays/modals.js:176` holds
    `'Can view'`, `'Can comment'`, `'Can edit'` and `'Full access'` — and the document holds the
    same strings: the share modal compares them (`q === perm`, `:222`) and the option list
    marks the selected one (`x === 'Can edit'`, `:192`). They are therefore data, exactly like the
    statuses and the roles, and they follow the same treatment: the stored value stays, and
    only the DISPLAY is a catalogue value (`common.perm.*`).

    The comparison must therefore compare the STORED value, not the catalogue value:

    ```js
    const perms = PERMS.map(id => ({ id, label: t('common.perm.' + id) }));
    ```

    and the selected option is marked by `p.id === perm` — `perm` is the value the document
    holds. In English the two are identical, so the rendering does not change; in French, the
    comparison still works because it never touches the translated text. A sweep that replaced
    the comparison operand with the catalogue value would pass the English tests and break the
    French interface in phase 7 — the failure the CONTEXT's deferral of the stored vocabulary
    warns about.

    **The markup.** The drawer and the modals carry the interface's most structural markup: the
    property rows, the alerts, the modal footers, the date pickers. Two rules keep the markup
    intact:

    - A phrase that is wrapped in an element in the source keeps its element. The catalogue
      carries the text; the tag stays in the template.
    - A label that is a property of an object literal — the `title` of a modal, the `hint` of a
      field — becomes a catalogue value, and the surrounding punctuation that is part of the
      sentence stays with the sentence.

    Update the allow-list: the literals extracted from these two files leave it, and it stays
    sorted.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a catalogue value → an overlay | the value is spliced into a drawer, a modal, a popover or the palette |
| a stored permission → a comparison | the permission comes from the document and is compared against the stored id |
| a document value → an interpolated catalogue value | the interpolated value comes from the document, i.e. from user data |
| `src/` → the icon bundle | every quoted token in a `.js` file under `src/` can pull a Lucide icon into the bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-49 | Tampering | a catalogue value → an overlay | high | mitigate | A catalogue value may carry no `<`, no `>` and no `"`; the phase-5 lint rejects it, and the interpolated values are escaped at the point of interpolation with the existing `esc()` (D-07, D-10) |
| T-06-50 | Tampering | a stored permission → the share modal's comparison | high | mitigate | The comparison reads the STORED id, never the translated text: a sweep that compared the catalogue value would pass the English tests and select nothing in French (D-08, I18N-07's groundwork) |
| T-06-51 | Tampering | the action keys and the icon names of the overlays | high | mitigate | They are machine identifiers and are never translated: a translated action key makes a control silently dead (D-08) |
| T-06-52 | Tampering | the icon bundle | medium | mitigate | The catalogue stays JSON and every key is dotted; the 174-name baseline is asserted by `test/build-locales.test.mjs` (D-10) |
| T-06-SC | Tampering | package installs | high | accept | This phase installs no package and adds no `dependencies` block |
</threat_model>
