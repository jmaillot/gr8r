<objective>
Give `dateFmt` and `timeFmt` an `'auto'` sentinel, so an unset preference follows the locale while an
explicit user choice still wins — without rewriting a single stored document.

Purpose: this is where the phase's most subtle decision lands. The preference bag in the shared
workspace document already stores `dateFmt: 'MMM d'` in every existing document, and the document
cannot distinguish "never touched" from "explicitly picked the default". D-04 resolves it: the
stored `'MMM d'` **IS** the sentinel — it means "follow the locale" — and it is resolved at READ
time, so no document is rewritten, no revision moves and the shared document is not written at
all. The two writers that carry the preference (`A.setPref` and `IN.prefSel`) must pass the
sentinel through verbatim, or it is lost on the first save. The settings page must show the
`'auto'` option as selected for a stored `'MMM d'`, and its preview must be computed by the
locale's own formatter rather than hard-coded.

Output: the sentinel test, the sentinel-aware `fmtDate()`, the date-format and time-format rows of
the settings page, the shared preference-value helper, and `test/i18n-prefs.test.mjs`.
</objective>
