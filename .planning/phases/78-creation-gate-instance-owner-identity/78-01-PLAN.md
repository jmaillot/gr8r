# Plan 78-01: Server — Creation Gate, Boot Contract, Operator Identity

**As a** self-hosting instance operator,
**I want** one explicit boot-logged `WORKSPACE_CREATION=true|false` gate decoupled from `ALLOW_SIGNUP`, backed by a persistent multi-operator identity,
**so that** workspace creation is decided server-side by the gate and managed by operators, not by implicit signup coupling.

## Artifacts this phase produces

- `WORKSPACE_CREATION` boot-frozen const with strict-token parse + boot-refuse (`logError` + `process.exit(1)`) + D-11-style boot log line
- Gate swap at `POST /api/workspaces` (server.js:6811) with keyed refusal `workspaceCreationClosed`
- `/api/config` `workspaceCreation` becomes a boolean
- Two new operator-gated endpoints: `POST /api/auth/operator/users/:id/promote` and `/demote`, with last-operator 409 guard and transactional audit rows
- New integration suite `test/creation-gate.test.mjs` covering the full token/boot/gate/endpoint matrix
- Locale keys `err.workspaceCreationClosed` + `err.lastOperator` in all 5 catalogues
- BASE_ENV update in test/helpers/server.mjs (Pitfall 5 regression shield)
