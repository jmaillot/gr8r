<objective>
Turn the catalogue format into an enforced contract, so a value that could inject markup can never
reach a rendered page.

Purpose: I18N-06 is not a convention, it is a test. A catalogue value that carries a `<`, a `>` or
a double quote can break out of a text node or out of an attribute — the codebase has 27
`aria-label` interpolations (184 `aria-label` occurrences in all), 49 `value` and 10 `title`
interpolations that a broken value would corrupt. This plan writes the lint that rejects such a
value, the shape rules that keep the catalogue a lookup rather than a grammar, and the invariants
that make the layer trustworthy: the registry agrees with the files on disk, and the project still
ships with no runtime dependency.

Output: `test/catalogue.test.mjs`.
</objective>

  <behavior>
    - a value containing a left angle bracket is rejected, and so is a value containing a right angle bracket or a double quote
    - a plural member containing a left angle bracket is rejected too — the lint walks the members of a plural object, not only the string values
    - a key that is not dotted and namespaced is rejected: a bare word, a key with a trailing dot, a key with an empty segment or a key with a space
    - a plural value whose members are not CLDR categories is rejected, and a plural value without an other member is rejected
    - a French key that the English catalogue does not carry is rejected — outside the documented contract fixture namespace, which exists to prove both directions of the lookup
    - a key whose French value carries a different set of placeholders than its English value is rejected
    - a value carrying a real ICU argument is rejected: "{count, plural, one {# task} other {# tasks}}" is rejected
    - a plain-text value that merely contains an English ICU keyword is ACCEPTED: "Select" and "Select…" (the literal the app renders at `src/overlays/popovers.js:414`, a phase-6 catalogue value) pass, and so does "C#"
    - the seed catalogues themselves pass every rule
  </behavior>
  <action>
    Create `test/catalogue.test.mjs` with `node:test` and `node:assert/strict`. It reads the
    catalogue files from `src/locales/` with `node:fs` (no bundler, no server) and applies the
    rules below to EVERY locale file, so a new file is linted the day it lands.

    The rules, each one a separate named test so a breach names itself:

    1. **No markup in a value (I18N-06, D-10).** For every value in every catalogue file — a
       string value, and every member of a plural object alike — assert the value contains none of
       the three forbidden characters: the left angle bracket, the right angle bracket and the
       double quote. The assertion message names the file, the key and the offending character, so
       the breach is actionable without opening the file. This is the rule that makes a catalogue
       value inert: the call sites splice the value straight into markup, so the value must not be
       able to close a text node or an attribute.
    2. **Flat, dotted, namespaced keys (D-05).** Every key matches
       `/^[a-z][a-z0-9]*(\.[a-z][a-zA-Z0-9]*)+$/` — at least two segments, each starting with a
       lowercase letter, no spaces, no trailing dot. A bare word is rejected, because a bare
       lowercase word can be mistaken for a Lucide icon name by the `lucideSubset()` scan in
       `vite.config.js:30` if it ever reaches a `.js` file. This is the second layer of defence
       behind the JSON file format.
    3. **The plural shape (D-06).** A value that is not a string is a plural object. Its members
       are CLDR categories only — `zero`, `one`, `two`, `few`, `many`, `other` — and it must carry
       an `other` member, because `other` is the fallback every locale resolves to. A plural value
       that is an array, a number, `null` or a nested object is rejected.
    4. **The English catalogue is the base (D-08).** Every key of every non-base catalogue exists
       in `src/locales/en.json`, with one documented exception: the `contract.` namespace. Those
       keys are the phase's fixtures — `contract.englishOnly` exists only in English and
       `contract.frenchOnly` only in French — and they exist precisely to prove the two directions
       of the lookup. Any other French key the English catalogue does not carry is rejected. The
       reverse direction is expected and is not a breach: the English catalogue may carry keys a
       non-base catalogue does not, and that is exactly the English fallback case.
    5. **Placeholder parity (D-07).** For every key carried by both catalogues, the set of
       placeholders in the two values is identical. A placeholder is matched with `/\{(\w+)\}/g`.
       For a plural value, the union of the placeholders of its members is compared. A French
       value that drops `{name}` or renames `{n}` is rejected, because the call site passes one
       shape of variables.
    6. **The interpolation subset (D-07).** No value carries an ICU construct. An ICU construct is
       an ARGUMENT: a brace group that names a type, as in
       `{count, plural, one {# task} other {# tasks}}`. The rule therefore rejects a value that
       matches `/\{[^{}]*,\s*(?:plural|select|selectordinal|offset)\b/i` — a comma followed by an
       ICU type keyword inside a brace group — and rejects nothing else. Two things this rule must
       NOT reject, because they are legitimate plain text:
       - a plain English word that happens to be an ICU keyword: the value "Select…" (the literal
         the app renders at `src/overlays/popovers.js:414`, and a phase-6 catalogue value) and the
         value "Select" must PASS. This phase exists to pin the contract BEFORE the strings move,
         so a rule that blocks phase 6 on a legitimate value is a rule that must be fixed now;
       - a bare `#`: the ICU hash token only means "the number" inside a plural argument, which the
         pattern above already rejects, so a plain-text value such as "C#" is legitimate and must
         PASS. Only the ARGUMENT form is ICU, never the character.
       The rule applies to every string value and to every member of a plural object alike. Plural
       VALUES are objects, so the keyword check adds nothing for them — it guards the members.
       `Intl.MessageFormat` is `undefined` in Node 24 and in Chromium, so the catalogue is a lookup
       and nothing more.

    The last test in the file asserts the seed catalogues pass every rule above — a lint with no
    green case proves nothing.
  </action>
  <acceptance_criteria>

    - the seed catalogues pass every rule
  </acceptance_criteria>
