# Phase 90 — UI Design Contract

> Visual and interaction contract for the Polish & Verification Sweep. Generated by gsd-ui-researcher from D-90-1..23 (90-CONTEXT.md) and 90-RESEARCH.md; draft for gsd-ui-checker.

**Scope:** three touched surfaces, no new page and no new overlay. (1) Instance > Governance: the operator management section becomes a seg-control switching between a **Super Admins** console (roster-first + promote-search) and the existing **Instance Roles** card (D-90-1); (2) the shared Backup page's run history gains per-run download / verify-checksum / location / kept-until / missing-blob chrome (D-90-7..11, 16, 23); (3) the backup task form gains an on-demand **Preview deletions** projection block (D-90-12..15). Plus one invisible behavioral line — restore-list invalidation (D-90-22). SC-4 (e2e) and SC-5 (DEPLOY.md) have no UI surface.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — zero-dependency vanilla JS (D-33-11); hand-rolled token CSS |
| Preset | not applicable |
| Component library | none — the project's own CSS class vocabulary (src/styles/*.css) |
| Icon library | `ic()` inline SVG set, `src/core/icons.js` (lucide-style glyphs; 12–14px inline) |
| Font | Geist / Geist Mono via `--font` / `--mono` tokens (unchanged) |

**Primary visual anchor:** unchanged per page. On Governance, the anchor is the Super Admins **roster panel** — the first panel of the section, roster-first is non-negotiable (CONTEXT §Specifics); the candidate search is supporting chrome below it. On Backup, the anchor stays the task/run history list — the new badges and CTAs are row-level supporting chrome, never a new focal panel.

**Mandatory page idioms to mirror (verified in 89 and still binding):**
- Every payload field renders through `esc()` — text nodes only, never raw interpolation (T-79-10). Query echoes, user names, emails, filenames, sha256, counts: all through `esc()`.
- **Payload-flag authority chrome (D-89-21, extended by this phase):** the client renders only what the server payload decided. Concretely: the download CTA exists only when the history payload's server-derived `location` field is `local` or `s3` (never when `missing` — D-90-9); verify-checksum CTA only for a non-missing run; the missingBlob warning only when the payload carries a count > 0; the kept-position badge renders the server-computed `{position, keep, scale}` verbatim — the client never computes retention (D-90-12/16, research Pitfall 1).
- All copy keyed: `t('page.governance.super.*')` / `t('page.backup.*')` / `tErr(code)` — never literal strings. Every new key lands same-commit in all 5 locales (de/en/es/fr/nl — D-90-20), gated by catalogue.test + i18n-scan + fr-parity + the pinned count ledger.
- Refusals surface as keyed toasts through the **closed toast-map** (`RESTORE_REFUSAL_TOASTS`, actions.js:4879) — new codes extend the map 1:1 with their ×5 keys (89-06 doctrine). Refused actions are audited server-side; the client only reports.
- 360px discipline: **no new overlay exists in this phase** (promote is single-click; demote/revoke stay inline-confirms). Any overlay added later on these surfaces must follow the `confirmModal` / `.modal` idioms (overlays.css) and the 89 test-5 rule: consequence text wraps, modal scrolls, nothing clips at 360px.

**Purpose:** roster-first operator management. The seed is explicit: "I only want to list people holding this role by default, with search serving to add other selectable Super Admins."

State in `S.ui.govSuperSeg` (`'admins' | 'roles'`); the stage joins `ROUTE_TEARDOWN.governance` (stale seg state never survives route exit). Mount gate unchanged: the whole section renders only for `isInstanceAdmin` (server payload D-112).

**States:**

| State | Rendering |
|-------|-----------|
| Loading (users payload absent) | existing `aria-busy` faint panel body (governance loading idiom) — never a fabricated roster |
| Normal — roster | `srow` rows for `is_instance_admin = true` ONLY (D-90-2): name + email + you-badge + Super-Admin badge, last-login faint, actions third cell verbatim from today's operatorCard (demote inline-confirm, revoke inline-confirm, owner-immune/self hints). ## Surface 2 — Backup run history: download, verify, kept-until, missing-blob (D-90-7..11, 16, 23)

**Purpose:** operators verify and retrieve archives themselves; retention becomes visible without trusting a date that GFS cannot promise.

**Row chrome (render-verbatim from the history GET payload — the payload gains server-derived `location` per 90-RESEARCH Pitfall 2; the client never probes, never ListObjectsV2, D-89-14):**

| Element | Condition (payload-flag) | Rendering |
|---------|--------------------------|-----------|
| Location badge | always | reuse `page.restore.locLocal/locS3/locMissing` — neutral `.badge` / `.badge.accent` for s3, `.badge` (faint styling per restore-row idiom, backup.js:343) for missing. No green/red on location |
| Download CTA | `location !== 'missing'` ONLY (D-90-9) | `btn-secondary btn-sm`, `downloadAction`; triggers `GET /api/backup/download?runId=` → Blob → `saveBlob` (src/core/download.js); `Content-Disposition` carries the stored archive name (D-90-8) |
| Verify-checksum CTA | non-missing run only | `btn-secondary btn-sm`, `verifyChecksumAction`; placement in the sha row is planner discretion (research: sha-row button vs menu — sha-row button is the default recommendation: it sits next to the digest it validates) |
| Kept-position badge | run belongs to a task with GFS retention | `.badge` + mono figures: `kept: {position}/{keep} {scale}` — computed server-side per request from the CURRENT policy (D-90-16); never stored, never client-derived |
| MissingBlob warning | payload count > 0 (D-90-23) | `.badge.red` + `ic('triangle-alert', 12)` + `missingBlobWarn` with `{n}` verbatim — the operator learns at creation, not at DR |

**States (verify-checksum is the only stateful action):**

| State | Rendering |
|-------|-----------|
| Normal | row as above |
| Verify in flight | button label → `checksumChecking`, `disabled`, row `aria-busy` — never a fabricated result (S3 stream-back can take seconds) |
| Verify — match | `.badge.green` `checksumOk` + faint `checksumLastCheck` with the payload timestamp |
| Verify — mismatch | `.badge.red` `checksumFail` + faint `checksumLastCheck`; **no toast** — the badge is persistent, durable feedback (an ephemeral toast next to a persistent badge is redundant); keyed copy is on the badge itself |
| Download refused | keyed toast via closed map: `backupRoleRequired` / `backupDownloadAdminOnly` / `restoreArchiveMissing` / `tooManyAttempts`; refusals audited server-side — the client only reports |
| Verify refused (throttle) | `err.tooManyAttempts` keyed toast (D-89-22: the re-hash reads the whole archive — throttle consumed even on refusal) |
| Download in flight | browser-native (saveBlob); no spinner chrome — double-click prevention via a brief `disabled` on the CTA until the fetch settles is sufficient |

**A11y:** every badge's text content is the message (icons are decorative); verify button carries a visible busy label, not just a spinner; the checksum result badge text changes, so screen readers re-read the row region. Focus: after a refused download/verify, focus stays on the CTA (toast is live-region announced).

**Responsive:** the badge + CTA cluster sits in a `flex-wrap:wrap` row at `gap:8px` — at 360px the CTAs wrap below the meta line; `filename`/sha keep `.mono.trunc` + `title` (existing runRow idiom, max-width 280–360px inline-block). Console history tables unchanged (`min-width` + horizontal scroll patterns).

## Surface 3 — Backup task form: Preview deletions (D-90-12..15)

**Purpose:** make GFS rotation visible BEFORE it eats runs. On-demand only — never per-keystroke, never client-computed.

**Structure:** `Preview deletions` (`btn-secondary btn-sm`) sits in the form's action row, beside `taskSaveAction` (not inside the retention fieldset — it is a projection of the WHOLE policy, daily/weekly/monthly/yearly together). Click → projection endpoint (dry-run of `assignGfsBuckets` + keep-N walk, no deletes) → result block renders below the retention rows:

```
.panel (margin-top:12px, inside the form panel)
  panel-b:
    h2 deletionsTitle (+ faint deletionsCount summary)
    4 groups, fixed order daily → weekly → monthly → yearly:
      .row: [gfsDaily badge-label] [count]  ← every group renders, 0 included
      count > 0 → toggle button (deletionsShow/deletionsHide, aria-expanded)
                 + detail list: one row per projected run (filename .mono.trunc + title)
    result state lives in S.ui (ephemeral) — cleared on task save/cancel/edit
```

**States:**

| State | Rendering |
|-------|-----------|
| Idle (not yet requested) | nothing renders — no projection is ever fabricated |
| Loading | `aria-busy` faint row, `deletionsLoading` |
| Never-run task (D-90-14) | keyed `empty()` row, `deletionsEmpty` — no fake projection |
| Result | title + `{n}` summary + four groups (counts include 0); groups with count > 0 expose the collapsible detail list (D-90-13: grouped by scale, count per group, collapsible detail, trunc+title on filenames) |
| Refused (throttle) | `err.tooManyAttempts` keyed toast (D-89-22 idiom — the projection reads every run of the task) |
| Unreachable | `tErr` fallback with `err.serverUnreachable` (existing toast idiom) |

**A11y:** the collapsible is a real `<button aria-expanded aria-controls>` over a list container (not a details/summary restyle — keeps the house button idiom); group labels are text; the trigger button announces its result by the block appearing directly below (focus stays on the trigger; the block is the next tab stop).

**Responsive:** group rows wrap; detail filenames truncate at the shared max-width idiom; at 360px the trigger button joins the save/cancel row's wrap.

## Behavioral contract line (no visual change)

**D-90-22 — restore-list freshness:** when a backup run observes a terminal status transition in the existing `backupPollTick`, `S.ui.restoreList` is invalidated (set null — never an unconditional refetch inside the 1s tick, research Pitfall 8) so the in-render kick (`backup.js:537`) refetches the restore list exactly once. The operator experiences: the restore list is current after a backup finishes, without reloading the page. Zero new keys, zero chrome — if you can see it working, it is wrong.

## Interaction Contract (trigger → outcome flow)

1. **Seg switch:** the section defaults to **Super Admins** (roster-first is not negotiable — CONTEXT §Specifics). Switching to "Instance roles" swaps the body to the rolesCard content verbatim; both views' data keep their existing in-render kicks; no refetch on switch.
2. **Search:** < 2 chars → roster only (D-90-3). ≥ 2 chars → candidates block appears below the roster: match count, promote-only rows (cap 10 + show-more + cap note). Searching = adding; the roster = managing. Separation is visible in the layout, not just the copy.
3. **Promote:** single click (non-destructive — no confirm dialog) → keyed success toast (`settings.operator.toastPromoted`) + refetch reconcile → the candidate disappears from results and appears in the roster, **no page reload** (D-90-5; mechanism = existing `A.operatorPromote` refetch idiom — planner discretion to keep or optimize).
4. **Demote / revoke (roster rows only):** existing inline-confirm stages verbatim (keyed hint + `btn-danger` confirm + cancel); refusals (`err.lastOperator`, throttle) surface as keyed toasts — D-118/D-119 semantics unchanged.
5. **Download:** CTA renders only when the payload's `location` ∈ {local, s3} (D-90-9). Click → `GET /api/backup/download?runId=` → Blob → `saveBlob` with the server's Content-Disposition filename (D-90-8, the stored archive name). Every refusal = keyed toast through the closed map + server-side audit (89 idiom); the successful download itself is audited server-side too — success-only (D-90-10, invisible to the UI). Success = the browser's own save flow; no toast needed.
6. **Verify checksum:** CTA on a non-missing run → busy state (`checksumChecking`, disabled, aria-busy) → payload `{ok, checkedAt}` → persistent green/red badge + `checksumLastCheck` timestamp rendered verbatim. Throttled attempts cost a try and return the keyed toast (D-89-22). The result badge persists on the row until the next check or rerender.
7. **Preview deletions:** click in the task form → projection endpoint → grouped-by-scale result with counts and collapsible details (D-90-12/13). Never client-computed, never per-keystroke, never auto-refreshed (D-90-12); result is ephemeral and cleared on save/cancel/edit.
8. **Kept-position + missingBlob:** render-only from the payload on every history render (D-90-16 server-computed per request from the current policy; D-90-23 payload-flag). The client contains no GFS math — zero exceptions.
9. **Restore-list freshness (D-90-22):** terminal backup transition invalidates `S.ui.restoreList`; the in-render kick refetches once. Invisible when correct.
10. **Every refusal** = keyed toast (`tErr` / closed map) + audited server-side; no banner, no read-only chrome.
