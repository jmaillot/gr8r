In src/core/api.js, add three new methods to the api object. Place them beside the existing auth-scoped methods (login, logout, me) — NOT beside members(). The auth-scoped methods use call() directly without a slug guard because /api/auth/* endpoints do not accept a workspace slug parameter.

The three methods:
- sessions(): calls GET /api/auth/sessions and returns the response.
- revokeSession(id): calls DELETE /api/auth/sessions/{id} where id is URL-encoded via encodeURIComponent(id). Returns the response.
- revokeAllSessions(): calls DELETE /api/auth/sessions/others. Returns the response.

Each method should use the same call() pattern as the existing auth methods. The call() function signature is call(method, path, body). For DELETE methods with no body, pass undefined as the third argument or omit it. Follow the exact pattern of the existing auth-scoped methods.

In src/core/utils.js, add a new export function called deviceLabel. Place it beside the existing isMac() function (around line 41). The function takes a single argument ua (the raw User-Agent string) and returns a friendly label string.

The function should:
- Coerce the input to a string using String(ua || '') to handle null/undefined.
- Detect the OS by testing the UA string against these patterns (case-insensitive where relevant): iPhone or iPad returns t('dev.ios'), Android returns t('dev.android'), Mac or Darwin returns t('dev.mac'), Windows returns t('dev.windows'), Linux returns t('dev.linux'). If no OS matches, return empty string for the OS part.
- Detect the browser by testing: Edg/ returns t('dev.edge'), OPR/ returns t('dev.opera'), Chrome/ returns t('dev.chrome'), Firefox/ returns t('dev.firefox'), Safari/ returns t('dev.safari'). If no browser matches, return empty string for the browser part.
- Filter out empty strings and join with ' · ' (space, middle dot, space). If both OS and browser are empty, return the em-dash '—'.

Every literal label in the function must be a t() catalogue key. Do not hardcode strings like "Mac" or "Chrome" — use t('dev.mac') and t('dev.chrome'). This is required by the i18n two-gate pattern (Pitfall P-D): if a literal string appears in a user-visible context that is not a catalogue key, the prebuild i18n-scan fails.

The function should be exported as a named export (export const deviceLabel = ...) or (export function deviceLabel(...)). Follow the existing export pattern in utils.js.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client API -> Server | The client sends requests to /api/auth/sessions endpoints. Untrusted because the client is the user's browser and can send crafted requests. |
| Locale catalogue -> Client render | The t() function returns strings from JSON catalogues. Untrusted in the sense that a missing key produces a fallback, but the catalogue files themselves are committed and reviewed. |
