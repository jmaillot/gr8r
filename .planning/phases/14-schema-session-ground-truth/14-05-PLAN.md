Close the single Phase 14 verification gap (D-28 client teardown wiring, 14-VERIFICATION.md truth 12): a genuinely revoked browser's general 401 paths bypass `signOutRevoked()` — the `gr8r:save-error` handler toasts the generic session-expired copy and tears nothing down, boot hydration redirects silently, and `refreshSessions()` swallows 401s. **Design decision (verifier human-verification item 3 — resolved from locked decisions, not silently):** the choice was a global 401 handler vs. per-call-site teardown. The locked decision mandates the general route: D-28 reads "A revoked browser's **next request** hits **the 401 handler**" (any request, one handler) and explicitly forbids "no silent redirect" — which condemns today's hydration path and per-site omissions. The implementation follows the codebase's own event-decoupling idiom (store.js cannot import the UI layer and dispatches `gr8r:save-error` instead): `call()` in api.js — the single fetch choke point — detects a mid-session revocation 401 and invokes one registered teardown callback, avoiding an api.js→actions.js import cycle. Per-site branches are retired rather than duplicated, so Phase 15 (PASS-02/03 password change, which kills other sessions) inherits the teardown for free. Rationale recorded here per the orchestrator's instruction.
