<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Server API response -> Client render | The sessions API response (id, userAgent, ip, createdAt, lastSeenAt, current) is rendered in the settings page. Untrusted because a server bug or man-in-the-middle could return crafted data. |
| Client revoke action -> Server API | The client sends DELETE requests with session ids. Untrusted because a crafted id could target a foreign session. |

## STRIDE Threat Register

Phase-level threats (T-14-01 through T-14-07) are owned by the registers of 14-03 (endpoint threats: T-14-01…T-14-04, T-14-07) and 14-01 (T-14-05 doc-strip, T-14-06 dormant schema). This plan introduces none.

## Plan-specific threats (14-04)

No new threats are introduced by this plan. The client UI code is a consumer of the server API, not a new trust boundary. The client renders server-supplied data (userAgent, ip) in the settings page, but all values are passed through esc() for HTML escaping. The revoke actions call server endpoints that are already protected by sameOrigin, requireUser, and user-scoped WHERE clauses. The signOutRevoked() function reuses the existing A.signOut() teardown, which is already trusted.
</threat_model>
