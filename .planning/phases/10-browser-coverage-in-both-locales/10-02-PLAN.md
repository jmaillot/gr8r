## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| test harness → e2e server | fixture accounts and invites are created against the throwaway e2e server only |
| browser context → app UI | visibility claims are read from the rendered DOM of the throwaway server, never from API responses |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-03 | Information disclosure | invite tokens in test fixtures | low | mitigate | Tokens belong to throwaway accounts on the throwaway server (mkdtemp DATA_DIR); they are asserted/used only within the test run and never logged beyond Playwright traces |
| T-10-04 | DoS | throttles across the growing matrix | medium | mitigate | Every account gets a run-unique `clientIp(run, tag)` — tag unique per account, not per flow (Pitfall 4); the /join visitor context carries its own forwarded-for header |
| T-10-SC | Tampering | npm installs | high | mitigate | No package installs in this phase; any install must first pass the package-legitimacy gate at a blocking human checkpoint |
</threat_model>
