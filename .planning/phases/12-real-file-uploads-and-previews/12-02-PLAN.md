<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL param→filesystem | `:id` from the URL and `name` from the doc record are user-controlled strings reaching path resolution and response headers |
| response→browser renderer | Served bytes are rendered by the browser (inline vs attachment decision is the XSS boundary) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-12-01 | Tampering/Elevation | GET /w/:slug/file/:id inline serving | critical | mitigate | D-06 fixed map: only png/jpg/jpeg/gif/webp/pdf serve inline; svg and everything else serve `Content-Disposition: attachment` + `application/octet-stream` (never the claimed mime), plus `X-Content-Type-Options: nosniff`; existing `script-src 'self'` CSP stays |
| T-12-02 | Tampering/Info disclosure | file id → path resolution | high | mitigate | Never build paths from the raw URL param: resolve `path.join(FILES_DIR, id)` and assert the resolved dirname is `FILES_DIR` (serveStatic guard shape, server.js:1813); the id must also match a record in the workspace doc after requireWorkspace — auth and existence in one check |
| T-12-03 | Info disclosure | unknown-id lookup | medium | mitigate | D-05: `requireWorkspace(req, res, slug, 'viewer')` then record lookup; both unknown workspace/unauthorized (404) and unknown id (404 + stable `fileNotFound`) return 404 — no existence oracle |
| T-12-06 | Spoofing | PDF iframe framing | medium | mitigate | File route builds its own header set (Pitfall 2): keep `nosniff`, drop `X-Frame-Options: DENY` / use `frame-ancestors 'self'` for inline types; attachment types never get an interactive default-src |
| T-12-08 | Tampering | Content-Disposition header | medium | mitigate | RFC 6266 sanitizer: strip CR/LF/quotes/control chars from the record's `name`, emit `filename="ascii-fallback"; filename*=UTF-8''<percent-encoded>` (~5-line hand-roll, zero-dep) |
</threat_model>

  <action>
1. In the top-level dispatcher, next to the 12-01 upload branch and BEFORE serveStatic: match `GET`/`HEAD` on `/w/([a-z0-9-]{2,40})/file/([A-Za-z0-9_-]+)`. Accept negotiation (D-13, Open Question 1 resolved: pathname route + Accept negotiation): if the Accept header contains `text/html`, delegate to the existing `serveStatic(req, res, url)` so the SPA bootstraps and `applyDeepLink` opens the preview modal; otherwise call the new `serveFileBinary(req, res, slug, id)`.
2. `serveFileBinary`: run `requireWorkspace(req, res, slug, 'viewer')` (D-05 — viewer minimum; unknown ws/unauthorized already get 404/403 with no oracle). Then load the workspace doc's `files` record for `id`; missing record → `fail(res, 404, 'fileNotFound', 'File not found')`. Resolve `path.join(FILES_DIR, id)` and assert the resolved dirname is exactly `FILES_DIR` (path-traversal guard, T-12-02); missing binary on disk → same 404 fileNotFound.
3. Headers per D-06 (own set, NOT `securityHeaders()` — Pitfall 2): `X-Content-Type-Options: nosniff` always; Content-Type from a fixed map derived from the record's extension via `fileType()`'s extension sets (quoted in src/ui/helpers.js:98-107): png/jpg/jpeg/gif/webp → their real image mime, pdf → `application/pdf`, svg → `application/octet-stream` + attachment (scriptable — never inline, T-12-01), heic/zip-family/doc/sheet/code/other → `application/octet-stream` + attachment (txt/md/csv may map `text/plain` but stay attachment — planner's discretion). Inline types (the 5 image mimes + pdf): `Content-Disposition: inline; filename=…` and `frame-ancestors 'self'` in a route-local CSP, no X-Frame-Options. Attachment types: `Content-Disposition: attachment; filename=…`, no interactive CSP needed beyond nosniff.
4. Filename per T-12-08: sanitize the record's `name` — strip CR, LF, double quotes and control characters; emit both `filename="<ascii-fallback>"` and `filename*=UTF-8''<percent-encoded>`.
5. Serve the bytes with the existing `sendFile` machinery shape (ETag/304 reuse optional); read via `fs.createReadStream` to avoid buffering.
6. Add `err.fileNotFound` to BOTH catalogues (parity test, Pitfall 7).
7. Tests in test/upload.test.mjs (seeding pattern: admin logs in, doc-PUT plants a file record, binary written under dataDir/files): (a) UPLOAD-03 — an authorized member fetches `/w/{slug}/file/{id}` with Accept `*/*` and receives byte-identical content with 200; an outsider (valid account, no membership) and an unknown id both get 404; an unknown workspace slug gets 404. (b) UPLOAD-04 — a planted `.svg` record serves `Content-Disposition: attachment` with Content-Type `application/octet-stream` and nosniff; a planted `.png` record serves inline `image/png` with no X-Frame-Options DENY header. (c) A navigation-style request with `Accept: text/html` returns the SPA HTML (status 200, text/html), not bytes.
  </action>
