# 94-03 — UAT Round-2 Fix Plan: clock preference wiring, Rotated filter, builder alignment

## Task 1 — UAT-2b: wire the dormant timeFmt preference

**Files:** src/core/i18n.js, src/core/theme.js
- Discovery: the Settings selector (auto/12/24) writes `timeFmt` but NOTHING reads it — `formatTime` always runs `cycle:'auto'` (locale-based → 12h for English). Latent bug.
- Fix, mirroring the dateFmt house pattern: export `setTimeFmt(cycle)` from i18n.js storing a module-level default cycle ('auto' sentinel); `formatTime` uses `options.cycle || timeFmtDefault` instead of `options.cycle || 'auto'`. theme.js `applyPrefs` calls `setTimeFmt(p.timeFmt)` beside `setDateFormat(p.dateFmt)` — unset → 'auto', behavior unchanged for users who never touched the selector.
- Owner action after deploy: Settings → Date & time → « 24 » → Next run renders 22:00 (and every other clock in the app follows).
- Do NOT add timeFmt to DEFAULT_PREFS (i18n-prefs.test.mjs pins its absence; unset = sentinel handled at read).

**Verify:** extend test/i18n-prefs.test.mjs: formatTime honours a stored '24' (module cycle default), 'auto' unchanged; `node --test test/i18n-prefs.test.mjs`.
