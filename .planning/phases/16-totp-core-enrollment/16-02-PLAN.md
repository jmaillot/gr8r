## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser cookie session → tfa routes | An authenticated-but-unverified cookie crosses into sensitive state changes — password step-up gates both directions |
| request body → verify paths | Untrusted code strings cross into TOTP verify and recovery burn |
| pendingTfa Map | In-process memory boundary — the secret must never cross to disk or logs |

| T-16-03 | Elevation of Privilege | POST /api/auth/tfa/enroll | high | mitigate | Password step-up (D-49): scrypt verifyPassword on { currentPassword } before any secret generation; arming 2FA on a stolen cookie is blocked |
| T-16-04 | Information Disclosure | recovery_codes rows + enable response | high | mitigate | sha256 hash-only at rest (D-09/D-51), plaintext returned exactly once in the enable response (D-53), never logged or persisted |
| T-16-05 | Spoofing | POST /api/auth/tfa/enable | high | mitigate | Verify-before-enable (TFA-03): no pending entry → no enable; ±1 window via totp.js verifyTotpCode; replay guard vs two_fa_last_step (D-04); D-11 2fa-verify throttle 5/15min |
| T-16-06 | Spoofing | POST /api/auth/tfa/disable | medium | mitigate | Password AND code (D-57); burned recovery codes rejected via used_at marker; distinct tfa-disable throttle budget |
