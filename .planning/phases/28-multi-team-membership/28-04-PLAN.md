<decisions_applied>
**Empty `teams[]` semantics (explicit decision, per the gap-closure contract):** a project with an empty `teams[]` is an *unscoped* project — every active member stays assignable. Rationale: 28-CONTEXT.md leaves assignment-intersection mechanics to the agent's discretion (no D-NN locks picker semantics), the existing project-visibility surface (`canSee`, store.js:263) treats non-restricted projects as broadly accessible, and strict-intersection ("no one") would silently break assignment on every project that has no teams configured. The inverse case — a *member* with empty `teams[]` (teamless is a valid state per D-03) on a scoped project — is excluded: empty set ∩ anything is empty.

**Currently-assigned out-of-set member stays visible:** if the task's current assignee (or subtask assignee) is no longer team-intersecting (e.g. teams changed after assignment), they remain in the option list so the UI never silently hides existing state; they can be unassigned or replaced. New candidates are filtered strictly.

**Bulk-assignee popover (`case 'bulk-assignee'`, popovers.js:407) is intentionally NOT filtered:** it operates across a multi-selection of tasks that may span different projects, so a single per-project intersection is undefined. This surface is outside the verifier's gap scope (truth 6 names only 'assignee', 'subassignee', and the ctx flow). Documented here to prevent a future verifier from re-flagging it as unplanned.

**Context-menu path needs no separate code:** `A.ctxAssign` → `ctxTo('assignee')` (actions.js:518-524) only sets `S.ui.pop = { type: 'assignee' }`, which renders the same popover case — filtering that case covers the context menu automatically.
</decisions_applied>
