# Phase 71 — Plan 04: Gap closure — subrow status chip visual offset (G-71-3, cosmetic)

**Gap source:** 71-UAT.md test 1, reported by the user: "the subtasks status are not aligned with parent task status column". Severity: cosmetic. Diagnosis: `.planning/debug/g-71-3-status-chip-visual-offset.md`.

**Diagnosis (verified in code):** the parent status cell renders `<button class="pillbtn">` (task-list.js:27) with `.pillbtn { padding: 0 7px; height: var(--h-sm) }` (components.css:595). The subrow status cell renders `<label class="stchip">` (subtask-popovers.js:85) styled with `display: inline-flex; gap: 6px` only (list.css:190) — no padding, no height, no radius/background. Cell content-boxes align (71-02/71-03 fixes, e2e passes ±1px) but the visible chip content sits ~7px left of the parent pill's content, and the chip lacks the pill affordance. The e2e spec measures cell content-boxes only — a metric blind spot.

## Artifacts this phase produces

- Modified `src/styles/views/list.css` — `.subrow .c-status .stchip` gains the `.pillbtn` visual contract: `padding: 0 7px`, `height: var(--h-sm)`, `border-radius: var(--r-sm)`. Background/hover intentionally NOT copied (the subchip sits on the parent hover surface already; the focus-within ring from WR-01 is retained). Preferred over stripping the parent's padding — preserves the pill affordance everywhere else.
- Extended `e2e/subtask-align.spec.mjs` — grow-only: new assertions measuring the chip's inner first-child left edge against the parent pill's content edge. Do NOT weaken or delete any existing assertion.

No renderer (`subtask-popovers.js`) or `task-list.js` edits, no i18n keys, no new dependencies.
