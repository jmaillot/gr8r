<assumption_delta_decision>
noun: the account locale (`users.locale`, a registry code)
decision: promote
rationale: The per-account code becomes the primary and only persistent representation of the
language; the workspace-document label is demoted to a read-once legacy seed input and removed
from every write path (DEFAULT_PREFS, both prefs merges, docSnapshot, the selector handler).
Nothing is added alongside the old representation. The invariant companion test is Task 1's
round-trip contract: every supported variant ('en', 'fr') round-trips PATCH → users table →
userPayload.
</assumption_delta_decision>

<objective>
The account becomes the single source of truth for the interface language. A nullable
`users.locale` column (registry code, per D-01) is added through the proven `ensureColumn()`
helper without a backup and without any boot-time write (D-02), delivered by `userPayload()` and
settable only through a new `PATCH /api/auth/me` (D-03) that never touches the workspace row or
its revision. In the same plan the language leaves the shared document pipeline: the legacy
`prefs.lang` key is stripped at both merge points so it can never resurrect into a save, and the
phase-7 throwaway label→code mapping is deleted together with the stored-label format it served
(D-01).

Purpose: LOC-03/LOC-04/LOC-05 are the storage half of the phase — without the account column and
the document-pipeline removal, the selector work in 08-02/08-03 has nothing honest to persist to.
Output: `server.js` column + endpoint + payload field, stripped `store.js`/`theme.js`, new
`test/locale-account.test.mjs`, extended `test/migration.test.mjs`, updated wiring contracts.
</objective>
