<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/auth/tfa/factors | authenticated user reading factor metadata (names/last-used — no secrets ever leave the server) |
| boot migration → SQLite | copies live 2FA state; double-copy or last_step loss would open a replay window |
| login second step | untrusted 6-digit code compared against N factors |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-31-01 | Spoofing | totp_factors verify loop | high | mitigate | Per-factor `last_step` replay guard (D-09/D-10) via `verifyTotpCode` matched-step compare; boot copy carries `two_fa_last_step` so no pre-migration code replays |
| T-31-02 | Spoofing | login TOTP branch | medium | mitigate | Existing attempts counter increments before comparison + `tooMany` budgets; D-11 one attempt per submission regardless of factor count — no per-factor attempt writes |
| T-31-03 | Information Disclosure | factor helper / boot copy | high | mitigate | Single decrypt boundary: helper calls `requireTotpSecret` only, never `decryptTotpSecret`; no `??`/`\|\|` fallbacks; envelope copied verbatim (decrypt-free); pinned by test/totp-encryption.test.mjs |
| T-31-04 | DoS | boot copy | low | accept | Copy is trigger-gated with per-row re-check inside one transaction; failure aborts boot copy, existing v1.5 login path remains until copy succeeds |
| T-31-05 | Tampering | factor name storage/display | low | mitigate | Names are either the fixed catalogue key (D-07) or validated free text at enroll (Plan 02); rendered via `esc()`/`t()` only |
</threat_model>
