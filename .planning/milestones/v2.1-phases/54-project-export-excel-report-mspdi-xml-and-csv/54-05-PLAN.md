    ESCAPING — escapeXml replaces ampersand, left angle bracket, right angle bracket, double quote and single quote with their five entities, in that order, on every text node and attribute value. Never build XML by spreading an object: emit from ordered template strings so child order is positional and reviewable.

    DURATIONS — parseEstimate reads the stored ASCII form: a number followed by m, h or d, returning minutes as the number itself, sixty times the number, or four hundred and eighty times the number; anything else returns null. workingDaysInclusive counts Monday to Friday days between start and due inclusive, in UTC. isoDuration renders minutes as PT hours H minutes M 0S with no zero padding beyond the schema form, and PT0H0M0S for zero.

    DATES — formatDateTime takes an ISO date and a time string and returns the date followed by T and the time, with no Z and no offset. Task starts use 08:00:00 and finishes 17:00:00 in the workspace local day. A milestone start and finish are the same instant at 08:00:00.

    DOCUMENT ORDER — emit, in this exact order: the XML declaration with UTF-8, the Project element with the short namespace http://schemas.microsoft.com/project, SaveVersion 12, Name (the project name, never a filename), Title, CreationDate from model.exportDateISO at midnight, ScheduleFromStart 1, StartDate from the project start at 08:00 or the earliest task start, FinishDate from the project due at 17:00 or the latest task finish, CalendarUID 1, DefaultStartTime 08:00:00, DefaultFinishTime 17:00:00, MinutesPerDay 480, MinutesPerWeek 2400, DaysPerMonth 20, DurationFormat 7, then the ExtendedAttributes block, then Calendars, then Tasks, then Resources, then Assignments. A collection with zero children is omitted entirely, never emitted empty (the base calendar is always one child, so Calendars is never omitted).

    EXTENDED ATTRIBUTES — define the five Text fields once at project level: Text1 188743731, Text2 188743734, Text3 188743737, Text4 188743740, Text5 188743743, each as an ExtendedAttribute with FieldID and FieldName.

    CALENDARS — one base calendar, UID 1, name Standard, IsBaseCalendar 1, one WeekDays block with DayType 1 through 7 where 1 and 7 are non-working and 2 through 6 work 08:00 to 12:00 and 13:00 to 17:00. The calendar is unconditional: it is emitted for every project, including a project with zero tasks, because CalendarUID 1 at project level must always resolve to a calendar that exists. Calendars is therefore the one collection the "omit when empty" rule never reaches.

    TASKS — one Task per exported row in model.rows order, then one per model.milestones entry. Child order inside a Task is exactly UID, ID, Name, Type, Start, Finish, Duration, DurationFormat, Milestone, PercentComplete, PredecessorLink entries, ExtendedAttribute entries, Notes. Type is 1. UID and ID are the same one-based number across tasks and milestones. Start is the row start or the project start; Finish is the row due at 17:00 or the start plus duration when no due exists. Duration is parseEstimate of the row estimate, else workingDaysInclusive times 480, else zero; a milestone has Milestone 1, Duration PT0H0M0S and Start equal to Finish. PercentComplete is the row progress clamped to 0 through 100. For each dependency id in the row deps that resolves to an exported task or milestone UID, emit one PredecessorLink with PredecessorUID, Type 1, CrossProject 0, LinkLag 0 and LagFormat 7, in that order; a dependency that does not resolve emits nothing. ExtendedAttribute values in order Text1 the key, Text2 the localized status, Text3 the localized priority, Text4 the joined label names and Text5 the raw estimate string, each omitted when its value is empty. Notes carries the plain-text description only when model.options.descriptions is true and the description is non-empty, and is omitted otherwise.

    RESOURCES AND ASSIGNMENTS — one Resource per distinct assignee name among exported rows and milestones, ordered by first appearance, with UID and ID as one-based numbers, Name and Type 1. The unassigned label is not a resource. One Assignment per task and resource pair, ordered by task then resource, with child order UID, TaskUID, ResourceUID, PercentWorkComplete, Finish, Start, Units 1, Work the task duration. Omit both collections when empty.

    TOGGLES — read every inclusion decision from model.options, the frozen set the model actually applied, never from a private copy of the flags. Descriptions gate Notes above; subtasks, completed and archived are already resolved into model.rows and must not be re-filtered here. Comments are the one recorded exception to R3's "applied identically by the xlsx, MSPDI and CSV writers" clause: the MSPDI schema has no comment element, and D-54-8 scopes comments to the `Tasks` sheet columns, so the MSPDI writer emits no comment content. Record that exception in the module header comment beside the R3 reference and assert the no-op in the suite; do not map comments onto an unrelated Project field, which would corrupt a real field rather than carry the data.
