# Phase 71 — Plan 05: Gap closure — assignee/priority/due content offset (G-71-4, cosmetic)

**Gap source:** user report after the G-71-3 fix: "you can align also assignee, priority and due date" — the same ~7px class of offset as G-71-3, on the other three meta cells.

**Diagnosis (verified in code):** the parent cells render `<button class="pillbtn">` (task-list.js cellAssignee/cellPrio/cellDue) with `.pillbtn { padding: 0 7px; height: var(--h-sm) }` — so the parent's visible content inset is 8px (cell) + 7px (pill) = 15px. The subrow assignee/priority/due cells render bare content (avStack / prPill / `.due` span) directly inside `.c-meta` (padding: 0 8px only, list.css) — content inset is 8px, so their visible content sits ~7px LEFT of the parent's. The G-71-3 fix (`.stchip` pill contract) closed exactly this for status; the other three cells need the same treatment.

## Artifacts this phase produces

- Modified `src/features/subtask-popovers.js` — the assignee/priority/due subrow cell content is wrapped in a single pill-contract element (reuse `.stchip`-style contract; a shared class such as `.stpill` mirroring `.stchip`'s padding/height/radius, or per-cell — executor's judgment, keep D-71-7: cells stay non-clickable display content, no data-a attributes).
- Modified `src/styles/views/list.css` — the pill contract applied to the new wrapper(s); the existing `.stchip`, `.c-meta`, `.subhead` and focus-ring contracts stay untouched.
- Extended `e2e/subtask-align.spec.mjs` — grow-only: inner-content alignment assertions for assignee, priority, and due cells on List and My Tasks. Do NOT weaken or delete any existing assertion.

No task-list.js edits, no i18n keys, no new dependencies.
