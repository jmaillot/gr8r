<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → Postgres | DB_URL credentials cross into pg Pool config; DSN must never reach logs |
| SQL rewrite layer | all queries pass through toPgSql — a bug here could alter statement semantics (SQLi/Tampering surface) |
| boot probe | unreachable/hostile pg endpoint at startup; error output is operator-facing |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-45-01 | Tampering (SQLi) | toPgSql rewrite layer | high | mitigate | rewrite is pure SQL-text transform of already-parameterized statements; never concatenates param values; every rewrite row unit-pinned in test/db-adapter.test.mjs; quoted-literal spans skipped |
| T-45-02 | Information Disclosure | connectDb boot errors / pool error logger | high | mitigate | log err.code + err.message only; never the DSN; pin test asserts `postgres://` absent from boot-failure output |
| T-45-03 | DoS | pg Pool defaults | medium | mitigate | explicit `max: 10`, `connectionTimeoutMillis: 5000`, `idleTimeoutMillis: 10000`; `pool.on('error')` attached so idle-client failures log instead of crashing the process (Pitfall 8) |
| T-45-SC | Tampering | npm/pip/cargo installs | high | mitigate | package-legitimacy gate satisfied: RESEARCH Package Legitimacy Audit lists pg 8.23.1 verdict OK (no [ASSUMED]/[SUS]); no blocking checkpoint required; reserved for phase summary |
</threat_model>
