## Interaction Contract (page behaviors)

### Governance page layout
`<div class="page wide" style="max-width:1200px">` — `.ph` header (h1 + subtitle), then two `sblock` sections:
1. **Workspaces** — filter input (`search-sm` + `data-in="govQ"`) and a `seg` control (All / Active / Archived) above a `.panel` containing a `.perm-t` table: columns Member-visible name · Slug (`.mono`) · Members (count) · Creator · Created (`ago()`) · Status badge (Archived = `badge amber`) · row actions (`btn-secondary btn-sm`: Archive / Unarchive; `btn-danger btn-sm`-adjacent Delete offered only on rows the listing marks eligible — but **the server is the authority**: a Delete on a non-empty workspace surfaces `workspaceNotEmpty` as an err toast, the client may not pre-filter silently).
2. **Operators** — relocated `operatorCard()` markup as-is (srow rows, D-90 inline-confirm stages `S.ui.operatorDemote` / `S.ui.operatorRevoke`, promote/demote/revoke actions); `settings.js` loses the card AND the mount call AND the actions/state relocate (Pitfall 9: grep `operatorUsers|operatorRevoke|operatorDemote` afterwards — hits only in the governance path).

### Data flow
Render-only from the operator listing response (T-60-05 doctrine, dashboard precedent): never from the client document. One fill loop with monotonic sequence + in-flight abort (dashboard.js:27-46 pattern). No 30s poll — governance is a low-frequency surface; a manual refresh affordance is optional (planner discretion) but auto-polling is out.

### Orphan disposition modal (D-05/D-06/D-08)
Opened from the delete confirm path when the workspace has members (`membersOf` payload). Built on `modalHtml`:
- One block per member: avatar (`av`), name + email, current role badge.
- Per-member control: a `seg` or select choosing **Reassign** / **Release**; when Reassign, two selects appear in the same step: destination workspace (options = `targets` payload: name + member count, workspace being deleted excluded) and role (`owner/admin/member` — D-08 list; viewer excluded).
- State lives in `S.ui.govDispositions = { [userId]: {type:'reassign', wsId, role} | {type:'release'} }`.
- Modal footer: Cancel + "Delete workspace" (`btn-danger`), **disabled until every member has a resolved disposition** — the visible enforcement of D-06. The server re-checks regardless (`dispositionRequired` keyed refusal → err toast).
- Submit sends dispositions with the delete call; modal closes on success, toast confirms, listing refetches.

### Confirmation gating summary (D-04)
| Action | Gate | Modal tone |
|--------|------|-----------|
| Archive | type the workspace slug | amber, archive icon |
| Delete | type the workspace slug | red, trash icon |
| Release member | type the member's email | red |
| Unarchive | click + confirm (no typing) | amber |
| Promote | none (mirrors Phase 78) | — |
| Demote / Revoke sessions | D-90 inline-confirm in the row (relocated as-is) | row-level |

## UI Considerations

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Workspace listing with zero workspaces | ✅ covered | `empty()` zero-state with documented "No workspaces" copy (Copywriting Contract); single-workspace instance renders one row — no special case |
| empty | Filtered list with no matches | ✅ covered | Documented "No matches" empty state, distinct from the zero-workspace state |
| loading | First visit of the page | ✅ covered | `aria-busy` faint busy body per panel (dashboard `busyBody` precedent); no skeletons required for a table this small |
| error | Non-operator deep-link → 403 | ✅ covered | Fullstate lock glyph + `err.code403` + `err.operatorOnly` + home button (dashboard.js:84 verbatim pattern); no workspace-existence leak |
| error | Listing fetch failure / server error | ✅ covered | Fullstate cloud-alert + "Try again" retry action; explicit retry, never auto re-kick while error state set (CR-01 precedent) |
| error | Action refusals (workspaceNotEmpty, dispositionRequired, lastOperator, already-assigned) | ✅ covered | Keyed err toasts, one per refusal — operator can tell which list to fix (Pitfall 5 separation preserved in copy) |
| zero-one-many | Delete flow with 0 / 1 / many members | ✅ covered | 0 members → confirm modal goes straight to slug-type-to-confirm, no orphan modal; 1+ members → orphan modal enumerates each; block-until-resolved enforced by disabled OK + server re-check |
| partial | Workspace whose owner membership is gone | ✅ covered | Creator column renders honest `—` (research Pitfall 1); never a fake name |
| long-text | Very long workspace names / emails in table cells and modal rows | 🧪 backstop | Cells use `.trunc` overflow behavior (established pattern); held-out client-surface test pins that a 200-char workspace name and a long email do not break the `.perm-t` row layout or the orphan modal footer |
| long-text | Slug typed into type-to-confirm | 🧪 backstop | confirmModal compares `S.ui.confirmText === typeName` exactly; held-out test pins that a slug with mixed case/whitespace does not pass until exact match |
| overflow | Large instance — hundreds of workspaces in the listing | ⚠ unresolved | Research flags small-instance assumption (CONTEXT discretion: "no pagination needed unless research says otherwise"). Contract: ship unpaginated; if the listing grows, this is a planner assumption to revisit — client may add client-side filtering only (name/slug filter), never server pagination in this phase |
