    **The tables.** The four tables in `src/core/constants.js` and the role map in
    `src/core/store.js` keep their ids and lose their display names:

    - `STATUSES` keeps `id` and drops `name`; the display comes from `t('task.status.' + st)`.
    - `PRIOS` keeps `id` and drops `name`; the display comes from `t('task.priority.' + p)`.

    **The role ids are capitalised, and the key shape is not.** The document stores the role
    `'Owner'`, `'Admin'`, `'Member'` and `'Guest'` — the pages compare them as
    `m.role === 'Owner'` (`src/pages/settings.js:232`) — while the phase-5 catalogue lint only
    accepts a key whose every segment starts with a lowercase letter
    (`^[a-z][a-z0-9]*(\.[a-z][a-zA-Z0-9]*)+$`, `test/catalogue.test.mjs:29`). The lookup
    therefore LOWERCASES the stored id before it builds the key:

    ```js
    export const roleLabel = role => t('common.role.' + String(role || '').toLowerCase());
    ```

    The stored value is untouched: the document still holds `'Owner'`, and the comparison
    `m.role === 'Owner'` still matches. Only the DISPLAY is a catalogue lookup.

    The **stored values never change**: the document still holds `backlog`, `todo`, `urgent`,
    `design`, `owner` and the file types. Only the DISPLAY changes, and it is now a catalogue
    lookup keyed by the stored id. That is the groundwork phase 7's I18N-07 stands on, and it is
    why the ids must not be translated.

    Every id of every table gets a key, and a test asserts the coverage — a vocabulary id
    without a key would make the interface show the key itself, because `t()` returns the key
    when it cannot resolve a value.

    Update the allow-list: the literals extracted from these two files leave it, and it stays
    sorted.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a stored id → a catalogue key | the id comes from the document and is used to build a key |
| a catalogue value → the chrome | the value is spliced into the sidebar, the topbar or the document title |
| a catalogue value → an overlay | the value is spliced into a drawer, a modal, a popover or the palette |
| `src/` → the icon bundle | every quoted token in a `.js` file under `src/` can pull a Lucide icon into the bundle |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-45 | Tampering | a stored id → a catalogue key | medium | mitigate | The key is built from an id that comes from the document, so a tampered document could name a key that does not exist; `t()` returns the key itself in that case, never an empty string, and a test asserts that every vocabulary id has a key |
| T-06-46 | Tampering | a catalogue value → a feature module | high | mitigate | The values carry no `<`, no `>` and no `"` (the phase-5 lint), and the interpolated values are escaped at the point of interpolation with the existing `esc()` (D-07) |
| T-06-47 | Tampering | the stored vocabulary | high | mitigate | The ids, the routes, the action keys and the icon names are never translated: the vocabulary changes its DISPLAY only, and the document still holds the same ids, so an existing document keeps working untouched (D-08, I18N-07's groundwork) |
| T-06-48 | Tampering | the icon bundle | medium | mitigate | The catalogue stays JSON and every key is dotted; the 174-name baseline is asserted by `test/build-locales.test.mjs` and a removed literal that was an icon's last reference turns that test red (D-10) |
| T-06-SC | Tampering | package installs | high | accept | This phase installs no package and adds no `dependencies` block |
</threat_model>
