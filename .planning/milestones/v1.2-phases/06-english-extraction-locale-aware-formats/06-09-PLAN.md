## The namespace allocation for this wave

| Namespace | Carries |
|-----------|---------|
| `page.auth.*` | the sign-in, the sign-up, the join and the onboarding screens |
| `page.design.*` | the design-system gallery's token labels and state names |
| `settings.*` | the settings sections, their descriptions and their option labels |
| `a11y.*` | the accessible names: `aria-label`, `data-tip`, `placeholder` |
| `common.*` | the words shared by more than one page |

## The two prototype pages, and what phase 7 will do with them

`src/pages/design-system.js` holds the two prototype routes (`pageSystem` and `pageStates`).
The research decision D11 keeps them out of the FRENCH catalogue — they are internal prototype
surfaces, not product screens. This wave still extracts their labels, because success criterion 1
says no user-visible literal is left inline in the interface sources, and because the allow-list
has to reach zero. The consequence is explicit and intended: **these keys will have no French
value in phase 7, so the two prototype pages keep reading in English in a French interface.** That
is D11's documented behaviour, not a leak into a product surface.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a catalogue value → a page | the value is spliced into a heading, a tab, a placeholder or an accessible name |
| a stored fragment → a page | the notification fragments and the activity verbs come from the document |
| the user's input → a page | the search query and the form values are interpolated into markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-30 | Tampering | a catalogue value → a page | high | mitigate | The values carry no `<`, no `>` and no `"` (the phase-5 lint), and the interpolated values are escaped at the point of interpolation with the existing `esc()` (D-07) |
| T-06-31 | Tampering | the demo values the pages pre-fill | low | accept | They are demo content, covered by the scanner's `DEMO_VALUES` set; the page shows what it shows today |
| T-06-32 | Information disclosure | the settings page | low | accept | The settings page shows the stored preferences it shows today; this wave translates no value around them that would expose more than the interface already shows |
| T-06-33 | Repudiation | the allow-list | medium | mitigate | A stale allow-list entry is a violation, so the meter cannot be padded; the scan proves the literals are really gone |
| T-06-SC | Tampering | package installs | high | accept | This phase installs no package and adds no `dependencies` block |
</threat_model>
