## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a catalogue value → a page | the value is spliced into a heading, a tab, a placeholder or an accessible name |
| a stored fragment → a page | the notification fragments and the activity verbs come from the document |
| the user's input → a page | the search query and the form values are interpolated into markup |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-53 | Tampering | a catalogue value → a page | high | mitigate | The values carry no `<`, no `>` and no `"` (the phase-5 lint), and the interpolated values are escaped at the point of interpolation with the existing `esc()` (D-07) |
| T-06-54 | Tampering | the stored activity verbs | high | mitigate | The verbs are never written in a translated form and the filters still parse the English they store; phase 9 restructures them into machine verbs. A translated verb would make the filter select nothing, silently |
| T-06-55 | Information disclosure | the notification fragments | low | accept | The fragments are stored content and are displayed as they are stored; this wave translates nothing around them that would expose more than the interface already shows |
| T-06-56 | Repudiation | the allow-list | medium | mitigate | A stale allow-list entry is a violation, so the meter cannot be padded; the scan proves the literals are really gone |
| T-06-SC | Tampering | package installs | high | accept | This phase installs no package and adds no `dependencies` block |
</threat_model>
