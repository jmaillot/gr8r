<objective>
Replace the last nine uses of the English `MON`, `MONL`, `WD` and `WDL` arrays with the locale's own
weekday and month names, and delete the arrays.

Purpose: the arrays are the last piece of hand-rolled English formatting left in the sources. A
calendar that says "Sun" in a French interface, and a mini-calendar whose header says "Su Mo Tu We
Th Fr Sa" because it slices an English array, are exactly the leaks this phase exists to close.
This plan swaps the nine call sites for the locale-driven `weekdayName()` and `monthName()` and
then deletes the arrays, so no English month or weekday name survives anywhere in `src/`.

Output: the four call-site files, the deletion of the arrays from `src/core/utils.js`, and
`test/i18n-dates.test.mjs`.
</objective>

## Declared deviation from the CONTEXT — the two-letter weekday header

The CONTEXT says, of `src/overlays/popovers.js:96`:

> *"the two-letter weekday header must become `Intl`'s `weekday: 'narrow'`, not merely be wrapped."*

This plan does **not** use `weekday: 'narrow'`, and the reason is the locked decision D-01 and the
roadmap's second success criterion, which both say the English interface must render exactly as it
renders today:

- `Intl`'s narrow weekday in English is ONE letter: `M T W T F S S` — Tuesday and Thursday both
  read `T`, Saturday and Sunday both read `S`. Today's header is `Su Mo Tu We Th Fr Sa`, which is
  unambiguous. `weekday: 'narrow'` would therefore make the English mini-calendar WORSE and would
  change the English rendering — the one thing D-01 forbids.
- The CONTEXT's actual requirement — *the header must come from `Intl` and not from an English
  array* — is fully honoured: the header is built from the locale's `Intl` short weekday name.

The plan uses `Intl`'s `weekday: 'short'` (`Sun`, `Mon`, `Tue`, …) and applies the SAME two
character truncation the source applies today (`WD[...].slice(0, 2)`), so the English header stays
`Su Mo Tu We Th Fr Sa` byte for byte, and the French header becomes `lu ma me je ve sa di` instead
of a French month of English letters. In the full calendar view — which today uses the arrays
WITHOUT slicing — the locale's short weekday name is used as is: `Sun`, `Mon`, … in English and
`dim.`, `lun.`, … in French.

If the reviewer prefers the CONTEXT's literal wording, the change is one option value
(`'narrow'` instead of `'short'`) in one file, and it costs the English mini-calendar header.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a date → an `Intl` formatter | the dates come from the document, i.e. from user data |
| the locale → the weekday and month names | the names are produced for the active locale |
| the calendar's markup → the DOM | the header is spliced into the page |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-06-13 | Denial of service | the weekday header | low | mitigate | The header is built from seven dates; `weekdayName()` reuses one cached `Intl.DateTimeFormat` per locale, so a render does not construct seven formatters |
