placeholder as `{count, plural, …}`. This plan resolves the count placeholder as `{n}`, and the

traceability trail stays honest; phase 6 and phase 7 author their catalogue entries against

  <action>
    Extend `src/core/i18n.js` with the plural engine (D-06, D-07). The rule: when the resolved
    catalogue value is an object and not a string, it is a plural value keyed by CLDR category.

    - The count is read from `vars.n`. The convention is fixed: the count placeholder inside a
      catalogue plural value is `{n}`, exactly as the seed catalogues write it. `{count}` is not a
      second spelling — one spelling, one contract. Traceability: D-07 writes the count placeholder
      as `{count, plural, …}`, but that literal is ICU syntax, which D-07 itself forbids and D-06
      replaces with a CLDR-category object; `{n}` is the concrete spelling of D-07's "the count
      placeholder" and the deviation is recorded in the plan's context block.
    - The category comes from `Intl.PluralRules`, never from a hand-written rule. Build one rule
      instance per locale and cache it in a module-level `Map` (an `Intl.PluralRules` construction
