<objective>
Make the login flow enforce a real second factor for enrolled accounts: after a correct password the server issues a short-lived challenge (row + separate cookie) and returns `pending2fa`; a dedicated verify route validates a live TOTP or burns a single-use recovery code and only then mints the session identity. Includes the D-03 budget carry-over, D-13 generic lockout copy, and the D-71 401-matrix proof that a pending sign-in is structurally anonymous.

Purpose: TFA-05 — the code, not the password, is what creates a session; a pending sign-in must be inert across every endpoint family.
Output: server.js login branch + verify route + challenge lifecycle + sweeper + D-13 copy swap; test/tfa-login.test.mjs covering TFA-05-1…7.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/auth/login | untrusted credentials; correct password on enrolled account must yield NO identity |
| client → /api/auth/tfa/login | untrusted 6-digit/recovery code + challenge cookie; this is the only path that mints an identity from pending state |
| challenge cookie → requireUser() | a non-session cookie presented to identity-consuming endpoints; must structurally match zero sessions rows |
