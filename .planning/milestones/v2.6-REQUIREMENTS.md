# Requirements: v2.6 — Exports Verification (Test 11)

**Milestone:** v2.6
**Status:** planned
**Source:** Phase 65 deferred UAT checkpoint (item A1) + Phase 999.1 backlog; research in `.planning/research/` (SUMMARY, MSPDI-SPEC, EXPORT-SURVEY, VERIFICATION).

## Goal

Prove the multi-level subtask tree survives a REAL round-trip with MS Project — close item A1. Automated structural pre-screen first (existing tooling only), then one manual import per format by the owner, verdict recorded. Export fixes only if the UAT fails.

## Functional Requirements

### REQ-EXP-01 — Automated structural pre-screen (3-level export fixture)

The existing export tests grow a 3-level fixture (task → subtask → sub-subtask) and assert,
**for each format**:

- **MSPDI:** `OutlineLevel = depth + 1` at every level (1/2/3), Summary flag present iff the
  row is followed by a deeper row (re-derived from the SERIALIZED XML, not the model),
  no upward level skip ≥2 between consecutive rows, DFS row order (parent before child).
- **xlsx:** rows in DFS order; dotted key + bold-parent + indent signals present. Document
  the known gap: cell-style indent is fixed at 1 level regardless of depth (research gap —
  not silently "fixed" in the verification milestone; product decision logged if UAT fails).
- **CSV:** rows in DFS order, dotted key carries the hierarchy.
- Subtask rows' due-date inheritance documented as-is (top-level task's due, model.js:227).

**Validation:** all assertions run in the existing `node:test` suites
(`test/export-mspdi.test.mjs` + export-model tests + `test/helpers/unzip.mjs`); zero new
dependencies; all existing gates stay green (1705 unit grow-only, chunk 500 kB, i18n).

### REQ-EXP-02 — Owner UAT: real MS Project import per format

The owner imports each export of a 3-level fixture into real MS Project, per
`.planning/research/VERIFICATION.md`:

- MSPDI via XML Import Wizard ("as new project") — **primary** verdict.
- xlsx via Excel paste (expected flat — recorded as such).
- CSV via the import wizard (expected flat — recorded as such).
- Captured evidence: wizard dialogs (verbatim for any repair dialog), Gantt screenshot
  showing the 3-level indent.

**Validation:** owner confirms hierarchy survives (or documented as a product limitation
with a logged decision).

### REQ-EXP-03 — Verdict recording + backlog closure

- Verdict (pass/fail per format) recorded in the phase verification doc; A1 checked off in
  ROADMAP.md Backlog (Phase 999.1 closed).
- If the MSPDI import fails or triggers a repair dialog: the defect is fixed in this
  milestone and re-verified through REQ-EXP-01 + REQ-EXP-02 before closure.

## Non-Functional Requirements

- **NFR-01:** Zero new runtime or dev dependencies (MPXJ rejected for this reason).
- **NFR-02:** Standing gates hold: entry chunk ≤500000 bytes on disk (currently 499940 —
  verification is test-only, but any incidental UI fix must respect the gate),
  i18n EN+FR committed together, lint 15-error baseline unchanged, 1705+ unit / 132 e2e grow-only.
- **NFR-03:** Export behavior for existing 2-level trees is unchanged (regression: all
  existing export tests keep passing unmodified in their assertions).

## Out of Scope

- New export formats; CSV/xlsx hierarchy enrichment (product decision deferred unless UAT
  forces a fix); incoming MSPDI import feature; MS Project round-trip automation (needs a
  dependency).
