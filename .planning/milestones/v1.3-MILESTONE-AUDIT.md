## Cross-Phase Integration (checker verdict: no blockers, no warnings)

All 9 new/changed auth routes wired end-to-end (server.js endpoint → api.js method → actions.js caller → UI surface):

GET /api/auth/sessions, DELETE /api/auth/sessions/others, DELETE /api/auth/sessions/:id12, PATCH /api/auth/password, POST /api/auth/tfa/enroll, POST /api/auth/tfa/enable, POST /api/auth/tfa/disable, POST /api/auth/tfa/login, POST /api/auth/login (pending2fa branch).

Six flagged seams — all verified in live code (orchestrator re-checked directly):

1. **D-04 replay guard** (SESS×TFA): `verifyTotpCode` returns `matchedStep`, rejects `s <= lastStep` (totp.js:61–77); persisted at enable (server.js L1522–1536) and login (L1644–1646); columns + `login_challenges` + expiry index asserted in test/migration.test.mjs:189–218.
2. **D-13 throttle copy**: all new throttle sites emit pinned generic `tooManyAttempts` (e.g. 2fa-login: `tooMany('2fa-login|ip|email', 5, 15min)` → `fail(429,'tooManyAttempts','Too many attempts. Try again later.')`); EN+FR client mapping present; no-copy-to-new-endpoints clause respected for genuinely new endpoints.
3. **signOutRevoked teardown** (D-28): single registration (`registerAuthRevokedHandler(signOutRevoked)`, actions.js:2141); api.js `call()` fires on exactly 401 + code `signInRequired` + signed-in + unlatched (api.js:86–89) with latch re-arm in `applyUser` (api.js:98); downstream revoke/password actions return early on 401 — no stacked toasts.
4. **Pending-session anonymity (TFA-05)**: `currentUser()` (server.js:1248–1259) reads only `parseCookies(...)[COOKIE]` — `gr8r_tfa_challenge` (CHALLENGE_COOKIE, server.js:81) is structurally invisible to `requireUser`. Challenge cookie selects only the throttle budget key and the challenge row; session minted inside the same transaction that deletes the challenge; `applyUser` exported solely for `doTfaLogin`'s verified response.
5. **AUTH-02 second-boot identity**: test/migration.test.mjs asserts `login_challenges` table + index parity between boot surfaces and dormant-column parity; `normalizeDoc` (server.js:369–374) strips fake `sessions`/`tfa` doc fields on every read.
6. **i18n catalogue**: EN/FR key-set parity (sole asymmetry: deliberate `contract.englishOnly`/`contract.frenchOnly` demo pair); i18n-scan gate green over final tree.

## E2E Flows — 5/5 complete, 0 broken

- **View/revoke sessions** (SESS-01/02/03): settings mount → GET → render (device icon, IP, this-device badge, per-row revoke, disabled revoke-all at ≤1 row) → DELETE → refresh. Opaque 12-char id prefixes, never the token hash; per-row delete user_id-scoped (`token_hash LIKE prefix%` under `user_id`).
- **Password change** (PASS-01/02/03): PATCH → current-pw verify + scrypt rehash + revoke-others in ONE `transaction()` → honest toast + banner; PASS-02 reuses the exact SESS-02 keep-current primitive (`token_hash != ?`).
- **2FA enrollment** (TFA-01–04): enroll (current pw) → QR via `renderQrSvg` (vendored encoder) + copyable secret → verify-before-enable sets `two_fa_enabled=1` → one-time recovery modal (transient `S.ui.recoveryCodes`, cleared by `recoveryDismiss`, never persisted — modals.js:48–56, actions.js:2492–2532).
- **Login second factor** (TFA-05): login → `pending2fa` parks client on '2fa' card (no user adoption) → dual-shape code field → replay-guarded TOTP or race-safe conditional recovery burn → session minted in the same transaction that deletes the challenge. Empty code rejected before the transaction; 3 wrong codes kill the challenge.
- **Mid-session revocation** (SESS-02/PASS-02): any 401 `signInRequired` → single `signOutRevoked` teardown → honest `err.signedOutElsewhere` toast (D-28); tested by test/auth-revoked.test.mjs.

AUTH-01/03 extras: recovery-burn honest post-landing report (D-73/D-74, actions.js:2677–2691 with WR-02 stale-count guard); Chromium e2e covers all three flows in EN+FR (55 2FA/password/session references in e2e/flows.spec.mjs).
