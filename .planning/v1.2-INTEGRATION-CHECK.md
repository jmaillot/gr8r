### 2. i18n-scan build gate covers phases 7/9 surfaces — **PASS** (I18N-01, UAT-10 precondition)
- The scan reads every `.js` under `src/` (only `src/data/seed.js` excluded, demo content by design) and is wired as `prebuild`/`prebuild:en` — no literal can bypass the gate into a build.
- `server.js` is intentionally outside the scan: phase 9's design keeps server messages as English source-of-truth plus a machine code (`fail(res, status, 'code', message)`, `httpError(status, msg, code)`); translation happens client-side via `err.<code>` catalogue keys. Verified: `test/error-codes.test.mjs` proves every emitted `fail()`/`httpError()` code has a non-empty `err.<code>` entry in BOTH catalogues.
- **PARTIAL residue (known, owned by phase 11):** 4 raw English fragments render inside French sentences (phase 7 `deferred-items.md` #1–4: `toast.moved` up/down, delete-project `<b>N task(s)</b>` splice, remove-access trailing sentence, guests-hint article). These are dynamic template splices the scanner families cannot see — logged, not silently broken. Phase 11 owns them.

### 3. Locale preference flow: selector → PATCH → pre-render application — **PASS** (LOC-01, LOC-03, LOC-04, LOC-05, LOC-06, UAT-06)
Full chain traced end-to-end:
1. `src/pages/settings.js` `langSel` — dedicated `data-in="langSel"` key, never the shared prefs document.
2. `src/actions/actions.js:2202` — `await setLocale(code)` (fires `gr8r:locale` → instant re-render, no reload) **then** `api.patchMe({ locale: code })`; failure toasts `toast.localeSaveFailed`.
3. `server.js:1265-1275` — `PATCH /api/auth/me` reads **only** `body.locale` (mass-assignment guard), validates against `LOCALE_CODES`, persists to `users.locale` (column added via `ensureColumn`, line 148 — LOC-05 migration); `userPayload` returns `locale`.
4. `src/main.js:181-183` — account locale (non-NULL) wins over negotiation and `primeLocale()` runs **before first render**; `primeLocale` is silent (no re-render loop).
5. `src/core/store.js:23` — the language lives on the account, never in the shared workspace document (LOC-04): no `S.doc.locale` references exist anywhere in `src/`.
- Live proof: `e2e/locale.spec.mjs` — instant switch without reload, survives reload/sign-out/sign-in, two members of one workspace keep their own language across reload + workspace switch + second context. All passed in the live run.

### 4. Server error codes translate in both locales; unknown-code fallback — **PASS** (ERR-01, ERR-02)
- Server side: `test/error-codes.test.mjs` static-extracts every `fail()`/`httpError()` code literal and asserts a non-empty `err.<code>` in en AND fr; live-server tests prove payload shape `{code, error}` with byte-identical English message (e.g. `invalidCredentials`, `passwordTooWeak`).
- Client side: `tErr()` resolves known codes with interpolated params in both locales; unknown code falls back to the raw server message; `tErr` can never echo the literal `err.<code>` key (gated through `has()`). All asserted in tests + proven on real server.

- `test/activity-verbs.test.mjs`, `test/i18n-vocab.test.mjs`, `test/migration.test.mjs` all pass. 25 `act.verb.*` keys in the catalogue.
